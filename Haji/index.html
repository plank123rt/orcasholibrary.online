Task 01 · do this first

Turn the chat archive into a feedback ledger

Buried inside the WhatsApp group are hundreds of clinical feedback messages, mixed in with ordinary conversation. Your job is to pull out every genuine feedback message and log it as one row in a local Excel file. Nothing gets summarized or reworded. You're transcribing, not interpreting.

Ground rules before you open anything

  • Work in Excel or LibreOffice Calc, saved to a local folder on this machine (or the drive Vikrant points you to). No Google Sheets, no Office 365 cloud autosave, no syncing the file anywhere.
  • The chat export and the ledger you build from it never get uploaded, emailed, or pasted into any website, chatbot, or AI tool (including for "just checking a format" or "just this one row").
  • Treat _chat.txt as read-only. You're extracting from it, never editing it.

Reading the raw export

Each message in the export starts with a timestamp in square brackets, then the sender, then a colon:

[04.09.23, 15:16:17] Sender Name: message text…

If a message runs several lines or paragraphs, it keeps going until the next […] timestamp appears, then that whole block is still one message. You'll see two very different kinds of messages:

  • Ordinary conversation: short back-and-forth between team members, reactions, scheduling, system notices like "changed the group icon." Skip all of this. It's not a row.
  • A feedback entry: a longer paragraph (or a few), usually opening with a patient's name and a rough date, then a description across things like excretion, digestion, energy, sleep. This is a row.

If you're ever unsure whether something counts as a feedback entry, log it anyway and flag it in the Notes column rather than skip it. It's easier to remove a row later than to find one you missed.

The ledger (exact columns, in this order)

One sheet, one header row (frozen), one feedback entry per row, in the same order they appear in the chat. Never re-sort the sheet itself; use a filter view if you need to search.

Row rules & a sane workflow

  1. One feedback message = one row, no matter how many paragraphs it runs.
  2. If a single message clearly reports on two different patients, split it into two rows sharing the same Message Timestamp, and flag both in column J.
  3. Go through the chat in date-order chunks (a month at a time is manageable) and update the progress tracker below after each chunk, so Vikrant can see steady movement rather than one big update at the end.
  4. A rough scan of the export suggests somewhere in the neighborhood of 1,500 genuine feedback entries. Treat that as a loose target for the total row count, not an exact number to hit.

Task 02 · once the ledger is complete

Teach a script to triage feedback like a clinician

The goal is to fill in the Sentiment Label and Keyword Tags columns automatically, a small rule-based script, running only on your laptop, reading and writing the local Excel file directly. This is you building the labelling logic yourself, not asking an AI to do the reading for you.

Illustrative example only (not from the actual chat)

"Since the last set, bloating is not there and she's still getting a burning sensation after spicy food, about the same as last time."

Positive phrase Negative phrase Neutral / no clear direction

Notice "bloating is not there" is positive even though "bloating" alone would normally flag negative. The word right before it flips the meaning. That negation handling is most of the difficulty here.

How to think about building it

  1. Build a starter vocabulary. Read 50–100 rows you've already logged and write down phrases that clearly mean improvement (reduced, gone, better, normal now, off the medication), phrases that clearly mean it's still a problem (still there, increased, painful, vomiting), and phrases that are purely descriptive with no direction (same as before, no change). Keep these as three lists in a plain text or CSV file. That's your lexicon.
  2. Handle negation. "Bloating is not there" and "bloating is there" share a keyword but mean opposite things. Have the script look a few words before a matched keyword for words like not / no / without and flip the result when it finds one.
  3. Score each row. Count positive-phrase hits vs negative-phrase hits after negation handling. Whichever count is higher wins; call it Neutral if they're tied or nothing matched.
  4. Check your own judgment against it. Manually label 30-50 rows yourself first (your honest read of positive/negative/neutral), then run the script on those same rows and compare. Every disagreement tells you what's missing from the lexicon.
  5. Repeat and expand. People describe the same symptom a dozen different ways over a long-running chat. Each pass through more rows will surface new phrasing. Fold it back into the lexicon.
  6. Log your reasoning, not just the label. Write the matched phrases into Keyword Tags alongside the Sentiment Label, so anyone reviewing the sheet can see why the script decided what it decided.

Tooling

Python with pandas and openpyxl to read and write the .xlsx directly is a natural fit. Plain string matching and regular expressions are enough for a first version. You don't need a machine-learning library at this stage; that comes later, once this labelled ledger exists to train on.

Local only · no cloud

You can absolutely ask an AI assistant to help you write the script itself (loop syntax, regex patterns, how to read an Excel file in pandas) using made-up example sentences you invent for the purpose. What never happens is pasting an actual row of patient feedback into any AI tool, chatbot, or cloud service. The script reads the local Excel file on your machine and writes back to it there. That's the whole pipeline.
